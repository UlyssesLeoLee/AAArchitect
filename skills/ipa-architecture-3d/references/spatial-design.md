# 语义三维架构：空间信息传递的设计契约

## 一、必须让空间可解释

这是**真实 Three.js/WebGL 三维语义图**，不是把 HTML 元素作透视倾斜，也不是把同一个二维图不断换色。

- X、Y、Z 轴各绑定一个真实、可核实、离散的架构属性。默认由 View 的 `dimensions.{x,y,z}.field` 给出；运行时可以手动更换三轴字段。
- 所有实体在所有 View 中共享稳定 `id`，关系只取自 `edges`，不得从空间距离臆造关系或协议。
- 底部坐标刻度、X/Y/Z 语义说明、Y 分层面、三种正交投影、跨域关系高亮，必须与实际坐标和数据一一对应。
- 切换 View 必须重算节点坐标、分组、轴名称、信息增益和关系过滤，连续平移动画不得使实体 ID 改变；当前选中 ID 必须保留。
- 单个坐标格的多个实体采用**规则方格排列**以避免遮挡。该格内的局部位移仅用于排版，不具有额外业务语义。
- 缺失属性显示 `—`；不以随机高度、猜测链路长度、没有数据来源的时延/风险/成本等数值填充 Z 轴。

## 二、空间有效性算法（关键）

将当前 View 的节点按 X / (X,Y) / (X,Y,Z) 分组，记不同组合数为 `g1` / `g2` / `g3`：

- X 的独立信息增量：`g1 − 1`
- Y 的独立信息增量：`g2 − g1`
- Z 的独立信息增量：`g3 − g2`

只有**严格正增量**才能被计为一个有效空间维度。具有多个值、但完全由前两个轴决定的 Z，不增加辨别能力，必须显示“冗余”并折叠，而不是吹嘘为“有效 3D”。例如：X 唯一标识每个节点时，Y 和 Z 即使名称不同，也不应计入有效空间信息。

采用确定性、非随机的单元布局。重排后检查：同一 cell 不相撞、标签可以从详情中完整读取、分层平面不会遮挡实体或关系。

## 三、信息分层与画面复杂度预算

| 粒度 | 用户想知道什么 | 内容 / 技术规则 | 建议上限 |
|---|---|---|---|
| L0 结构扫描 | 系统边界、分区、空间分布 | 轴、组、层、要素数量；弱化关系 | 每个 View 6–18 个节点优先 |
| L1 关系审查 | 实体之间发生了什么 | 方向、类别、跨信任边界关系；支持按轴类别聚焦和点击高亮 | 不超过 24 个全局同时显著显示的关系 |
| L2 设计证据 | 为什么这样设计 | 节点 ID、责任、环境、信任域、证据、相邻关系和待审查控制 | 仅详情面板完整显示长文本 |

超过 24 节点或者 24 条关系时，Skill 应主动要求模型拆成有边界的子 View，或提供初始聚焦类别。**不能通过缩小字体、缩窄节点或叠加无关特效来容纳无限信息。**

## 五、二维版（2D 平面）契约

3D 与 2D 是**同一架构事实的两种表达**，读者自行选择，不是主次关系。2D 不是把 3D 压扁，也不是把类别字符串罗列出来。

- **必须是真实二维**：原生 SVG（DOM 节点 + `textContent`），无 WebGL、无 CSS3D、无 `transform: perspective`、无图片旋转。
- **轴要有视觉语法，不是文字标签**：

| 维度 | 二维中的表达 | 必须同时呈现 |
|---|---|---|
| X | 纵向分层带 | 轴名 + 类别名 + 该带节点数 |
| Y | 横向泳道 | 轴名 + 类别名 + 该泳道节点数 |
| Z | 虚线**包含容器** | 容器标签 + 降级说明（平面无纵深） |

- **Z 必须诚实降级**：平面没有第三根空间轴，Z 只能表达为「同组归属」（包含关系）。界面上必须写明 Z 是分组标签而非空间轴，并把每个轴的类别数与独立信息增量一并列出，让读者判断该维度到底贡献了多少信息。
- **空格子是信息**：某个泳道在该分区没有组件时，显式标注「无组件」，不得留白，否则读者会误判为渲染缺陷。
- **关系可读**：使用正交折线（直角路由）而非随机曲线；跨信任域用暖色并配图例；图例同时解释关系线、跨信任域、节点核实状态与 Z 分组。
- **两版一致**：2D 与 3D 共用同一份 `dimensions.{x,y,z}.field`、同一套节点 ID 与证据。切换渲染模式不得改变轴字段、节点数、关系数或任何架构结论。
- **可访问**：SVG 需 `role="img"` 与说明性 `aria-label`；每个节点可聚焦（`tabindex`）并支持 Enter/Space 选中，键盘用户不依赖 WebGL 也能完成全部审查动作。
- **降级要明说**：WebGL 启动失败时仍然提供完整 2D，但必须显式声明「3D 未能启动」，禁止把 2D 降级伪装成正常 3D 渲染。

## 六、图形和交互精度

- **布局确定性**：同模型、同轴字段、同 View，输出位置保持不变；不使用随机力导布局或难以复审的每次变化。
- **节点**：在可见信息层显示短名称 + 稳定 ID；长描述和依据仅在侧栏。画布标签支持截短，但不能删去侧栏原文。
- **关系**：带箭头的 3D 连线，来源/目标严格对照数据。跨信任域关系使用暖色，其他关系使用冷色；色彩之外，右侧还显示数量和详情。
- **照明**：保证几何体有面、体积、遮挡与透视；避免光污染、动态粒子、无关贴图和循环旋转。
- **投影**：3D 透视 + XZ 俯视 + XY 正视 + ZY 侧视，通过互补方向核验坐标语义。支持 OrbitControls 平移、缩放、旋转和恢复。
- **筛选**：X/Y/Z 坐标轴各可选字段，也能选择一个具体类别聚焦。聚焦以降低其他节点可视强调实现，不改变系统事实。
- **连续性**：切换视点时，同 ID 的节点按旧坐标至新坐标插值；缺席节点收缩，不在当前 View 的选中节点 ID 仍保留并明确提示。
- **可读性**：UI 主标签不依赖纯色/图形暗示；对照所有三种语言的文本长度和布局溢出；`prefers-reduced-motion` 时禁用明显动画。
- **WebGL 失败**：给出真实错误及可审阅的文本节点列表，并提供完整 2D 平面视图。禁止假装 CSS3D 就是真正 Three.js，也禁止把 2D 说成 3D。

## 七、必须进行的自审

1. 随机选择两个节点，观察其 X/Y/Z 分类位置是否与 JSON 属性一致。
2. 检查有效维数：Y 若不能拆分任一 X 分组，或 Z 若不能拆分任一 XY 分组，不计为独立信息轴。
3. 逐个 View 对比对象集合与关系集合，确认未绘制悬空边、隐式协议或擅自增加节点。
4. 检查高密度场景：标签、箭头、坐标刻度无遮挡；必要时减少单视图范围。
5. 选择一个跨信任域关系，检查详情中的控制和证据；未确认应显示为待审查，不得填补推测。
6. 切换 View、切换轴、切换摄像机、筛选类别并恢复；确认实体 ID 不变。
7. 用 `zh-CN`、`ja-JP`、`en-US` 构建验证，检查界面、示例文本、审查解释均已本地化。
8. 逐个 View 在 2D 与 3D 之间来回切换，确认轴字段、节点计数、关系集合完全一致，且 2D 的分层带/泳道/分组确实表达了维度含义而不是堆砌类别。
9. 断开 WebGL（或使用不支持 WebGL2 的浏览器）确认 2D 仍完整可用，且界面明确说明 3D 未能启动。
