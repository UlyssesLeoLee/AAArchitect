# 日本 IPA 项目设计质量审查映射

**定位**：这是应用于架构网页交付的内部质量闸门，引用 IPA 公开资料作为检查方向；不是 IPA 官方认证或宣称达到某个未公布的审定等级。

| 参考背景 | 本 Skill 的落地约束 | 验证方式 |
|---|---|---|
| IPA 共通フレーム2013：系统开发过程 | 区分需求、架构构成、事实依据、审查事项；分清逻辑/运行/部署等视点 | model/views 的 stakeholder、concerns、questions、evidence |
| IPA 非機能要求グレード2018 | 可用性、性能与扩展性、运维与保守性、移行性、安全性、系统环境及生态等非功能关注点的梳理 | 仅展示具证据的措施，不以颜色伪造 SLA、加密、容灾、MTTR 等指标 |
| ISO/IEC/IEEE 42010:2022 | 架构描述应明确利益相关方、关注点、视点和视图关系 | 每个 View 有其审查意图、具体维度、事实映射与跨视图一致性 |
| 日本 IT 项目中的基本设计/方式设计审查惯例 | 短标题、术语一致、层级清晰、尽量避免视觉冲突；确保变更可追溯 | 日语本地化、完整原文留在详情、稳定 ID、零臆造 |

## 审核通过门槛

- P0：存在非 Three.js 的假三维；脱离架构事实绘制虚构节点/连接；证据不足却写成确定事项；三轴无事实依据却声称 3D 信息价值；交付语言与 `--lang` 不符。**禁止交付为完成。**
- P1：运行时引用与数据模型不一致、View 切换不能重算三轴、跨安全边界无警示、重要标签长期重叠、关键交互不可用。**禁止交付为生产就绪。**
- P2：过长说明/多余装饰/局部非关键标签截断/辅助配色不一致。可交付示例但需明确缺陷。

## 质量门槛流程

1. 静态验证 model Schema + 证据 + 三轴有效信息增益。
2. 单元测试布局唯一性 / 类目切换 / 多语言构建。
3. 在有 Node/npm/支持 WebGL2 的真实浏览器执行打开、切换、截图复审。
4. 各 View 审核语义三轴、视觉密度、俯视/正视/侧视、筛选、关系高亮和错误状态。
5. 对每一条已标明的技术事实保留实际来源；安全跨界连接提供控制或待确认标识。
